Troubleshooting

MAVROS and ArduSub integration

Inspect SITL and MAVROS logs before changing dependencies. Use the tested ArduSub commit 571e8c7bd3793fce1bc5184a2f6586feb8a616e5 and MAVROS 2.14.0 as the starting point. ArduSub, MAVROS, and the Gazebo plugin must remain compatible. Do not delete an existing checkout to change versions.

ArduSub

Inspect the checkout and its submodules first:

cd ~/ardupilot
git status --short
git submodule foreach --recursive git status --short

Save local changes before switching versions. To restore the tested revision:

git fetch origin
git checkout 571e8c7bd3793fce1bc5184a2f6586feb8a616e5
git submodule update --init --recursive

Follow the ArduSub installation instructions for prerequisites, then rebuild SITL when starting it. Do not use -N for the first start after changing the source revision.

MAVROS

Inspect and preserve local changes, then check out the tested version:

cd ~/suave_ws/src/mavros
git status --short

After saving local changes:

git fetch origin --tags
git checkout 2.14.0

For another version, update the MAVROS entry in suave.repos and explicitly check out that same tag, commit, or branch in the existing repository. Editing the manifest does not change an existing checkout. vcs pull src pulls the currently checked-out branches and does not apply manifest versions.

Rebuild the workspace after changing MAVROS:

cd ~/suave_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install

For campaign failures, use the runner diagnostics and inspect the reported attempt logs before retrying.
